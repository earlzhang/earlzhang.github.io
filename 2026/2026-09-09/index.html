Agent 没有终局赢家

September 9, 2026 · 5 min · Earl
Table of Contents
  • 独行者的工具
  • 纯文本的复仇
  • 三十年邮箱战争的镜像
  • 流动的自由

T.S. 艾略特在《四个四重奏》（Four Quartets）的第三乐章《干燥的萨尔维奇斯》（The Dry Salvages）里写道：

“I do not know much about gods; but I think that the river
Is a strong brown god—sullen, untamed and intractable…”
（我不太懂神明，但我以为河流是一位强有力的棕色神祇——不驯、桀骜、难以驾驭……）

起初人们敬畏它，视作通途；后来它成了货运通道，人们便自以为将它驯服；直到它再次漫溢，提醒人们它的不可征服。

最近国内的 C 端 AI Agent 大战好不热闹。腾讯的 WorkBuddy、字节的豆包工作、阿里的千问办公接连登场。大厂带着移动互联网时代的肌肉记忆，试图重演当年打车、外卖或社交软件的故事——巨额补贴、圈地建墙、赢家通吃，最终迎来一场一统江湖的“终局”。

但坦率讲，这场看似剑拔弩张的战役，或许注定不会有他们渴望的终局。

因为 Agent 从骨子里，就不是一个能被水泥大坝锁死的世界。

独行者的工具#

大厂之所以对终局抱有执念，是因为习惯了网络效应的红利。

微信的护城河是关系链，你不在里面就会失联；外卖与打车的壁垒是双边供给密度，骑手与司机不够，服务就无法运转。它们都有着极强的排他性与网络效应。

但桌面级 Agent 完全是另一回事。

说到底，它是一个属于独行者的生产力工具，更像一个高级的执行外壳。我用豆包工作清洗了一份财报，导出的表格发给你，你用千问办公继续跑分析，整个协作链路毫无阻碍。

生产力工具天然没有社交排他性。

更何况，随着Agents.md、MCP、Skill这些统一接口与标准协议的普及，各家在操作桌面、调用文件等执行能力上的差距，正在以周为单位被抹平。底层模型的推理能力，在激烈竞逐中也难以拉开代际鸿沟。

你用哪一家，既不妨碍你与同事协作，也不妨碍你随时换到另一家。

纯文本的复仇#

在传统软件商业史里，构筑护城河最牢固的手段，其实是格式垄断。

当年微软能靠 Office 统治桌面三十年，关键支柱就是 .doc 与 .xls 这些盘根错节的专有格式。任何对手只要在排版引擎或公式兼容上差了 1%，打印出来的合同排版错位，用户就会立刻倒戈回微软。格式的非标与复杂，天然是厂商最高耸的城墙。(当然，WPS近年的崛起，则是信息国产化的另一个叙事了)

是的，Agent 体系的底座，却正好相反，却全盘建立在最古老、最透明的纯文本之上。

知识库用 Markdown，结构化数据用 JSON 或 CSV，业务逻辑直接交给一段通用的 Python 脚本。

纯文本没有任何私有解析壁垒。谁解析出来的换行与加粗都一模一样，厂商没有任何格式绑架的空间。

更要命的是，连大脑都是可插拔的。

今天某个模型推理出色，填入 API Key 就能调用；明天另一款模型性价比更高，改一行配置就能无缝平替。就如我，作为 Windsurf 的资深拥趸，跳到各类新兴开发终端，交互范式高度同构，迁移成本几乎为零。

当输入是通用文本，输出是开源格式，连思考的大脑都可以随时更换，传统软件赖以生存的围墙便荡然无存了。

三十年邮箱战争的镜像#

这种局面并不陌生。如果你翻开互联网最古老、也最反直觉的软件品类——邮箱客户端，就会发现历史早已写好了剧本。

邮箱的底层协议 SMTP 和 IMAP 几十年未变，但这个赛道三十年来新品从未断绝。从早年的 Sparrow、Mailbox，到成就张小龙的Foxmail，到后来的 HEY、Superhuman，再到如今各类 AI 邮件工具，创业者前赴后继。

核心原因在于：协议完全开放。

任何团队写一个漂亮的交互界面，用户填入账号，第一天就能把过去十年的历史邮件完整导入，毫无冷启动门槛。全世界每天有海量高净值人群浸泡在邮件里，只要一款新产品能靠极致的审美或交互帮用户每天省下二十分钟，就总有人愿意掏钱买单。

但这也是它最残酷的宿命。

因为没有专有格式和关系链绑定，小而美的邮件客户端可以活得很滋润，却永远无法建立垄断帝国。你发明的滑动归档、延时发送或智能摘要，大厂花几个月就能原样跟进。最终，明星产品要么被收购关停，要么长尾共存，真正占据大盘的，永远是底层的服务系统与系统自带工具。

是的，今天的 C 端 Agent 客户端，几乎就是在高清晰度地重演这场邮箱战争。

未来依然会有层出不穷的垂类客户端涌现，但不会有任何一个第三方客户端能成为赢家通吃的超级平台。

流动的自由#

你可能会问，既然 C 端成不了垄断平台，大厂为什么还要如此大动干戈？

想想也是，当年 Outlook 能长青，本质不是靠作为邮件客户端本身，而是背后绑定的 Exchange 服务器与企业 IT 体系。

今天大厂的真实着眼点，或许同样不在 C 端客户端这点界面上——阿里的背后是钉钉与云端算力，腾讯的背后是企微与微信生态，字节的背后是飞书的工作流。

C 端的混战，更像是一场算力管道的铺设与用户习惯的练兵。

战局的演进大致会走向清晰的分流：大众泛办公沦为大厂争夺云算力消耗的免费搭头，但每一家巨头都希望用暂时的免费额度占领用户心智。

至于专业用户与极客则会用脚投票，除了Cluade Code或者OpenAI Codex这样SOTA模型的亲儿子，恐怕还是会坚守更开放、更透明的纯文本与命令行工具，比如Pi、DSH等。

回到艾略特的那句诗。大厂习惯了用移动互联网的逻辑去构筑水坝，试图把每一次技术变革都变成可以收租的水库。

但在 Agent 的世界里，纯文本和开放接口就像那条未被驯服的河流。它不属于任何一个码头，也无法被任何一道闸门彻底截留。

没有终局赢家，或许才是这场技术浪潮给使用者最好的馈赠。大厂在岸边竞相提供更充沛的算力与更精巧的工具，而顺流而下的我们，手里始终握着随时可以靠岸、随时可以带走的自由。

本文基于我的观点，由Gemini 3.7 Flash执笔
